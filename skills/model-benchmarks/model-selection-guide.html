5. OpenCode Go plan & pricing ($10/mo)

OpenCode Go ($10/mo) and Go Plus ($40/mo) are optional subscriptions that route curated open models through OpenCode infra with a monthly dollar allowance instead of the free shelf's per-day request cap. Token prices are identical on both plans; only the usage limit differs. After the limit, pay-as-you-go console balance kicks in (enable "Use balance") — or you fall back to the free models (still $0, daily-capped). Connect via /connect → OpenCode Go and pin models as opencode-go/<model-id>.

14. Operational resilience

No native failover exists in opencode (confirmed vs config schema + feature request #7602): single agent.<name>.model, no retry/backoff keys — only provider.<id>.options.timeout/headerTimeout/chunkTimeout. At 300+ calls/hr the loop dies on 429 unless you add rotation. Achievable design: (1) paired agents (reviewer + reviewer-fallback, different vendors) switched manually or via wrapper catching 429/FreeUsageLimitError with exp-backoff+jitter and --model rotation; (2) OpenRouter models:[primary,fallback] + allow_fallbacks for automatic in-gateway failover (+ per-endpoint uptime API for routing); (3) community plugins/proxy (auto-fallback, circuit-breaker) — vet before trusting; (4) never use *-free Zen IDs for 25-step loops. Reliability notes: Zen has no status page/SLA (quota, not uptime, is the failure mode); Groq has a real per-model status page; Google free = sheddable; NVIDIA trial has silent removals.

Deprecation (2026-10-18): DS V4 Pro/Flash retired (off NVIDIA + Eng chart; OR still routes -0731); M2.7, Qwen3.5/coder, StepFun, Inkling, GPT-OSS-120B off NVIDIA (102 → ~56); Kimi K2.6/K2.7, GLM-5.1/5.2 off Eng chart. Weight boring+stable; re-check via Zen deprecation table + inventory.

16. Mini-eval protocol (run before re-pinning)

Ten leaderboards lose to ten of your diffs. Corpus: 10 recent real diffs covering bugfix, security, feature, dep-bump, test-only, ops, refactor (frozen patches). Contenders: 2–3 (same frozen reviewer prompt, temp 0.1, fresh session each, strip model IDs, judge blind). Judge must be pinned — record model id + version + date in the scorecard; the answer key stays sealed until scoring is done; disclose any deviation (the 10-18 run unsealed the key mid-run after a route failure — scored rubric-structured, bias risk acknowledged). Log $/run + wall time + delivery per diff. Rubric per run (1–5): true positives · false positives (weight ×3 against) · actionability (concrete fix + file:line) · format compliance. Decision: rank by (blocking issues caught − false alarms), break ties by $/run. Cost ≈ 30 runs × per-run cost — compute from §12 first. Re-run quarterly or when the shortlist changes; log scorecards under skills/model-benchmarks/snapshots/evals/.

Statistics the protocol respects: with n=10 paired diffs only tier gaps resolve — net-score gaps under ~10 points are noise (10-18: +32 vs +30 is a tie for first; +9 is a tier below). The pin decision therefore rests on delivery-adjusted depth and wall time, not the net gap. Sequential stopping: minimum 6 diffs (cover ≥4 types); drop a contender early only on mathematical futility (even a max-rubric sweep of remaining diffs can't overtake the leader's net); after 2 consecutive provider DNFs, pause the route, not the model — re-run those diffs on a fallback route before scoring (timeouts are route evidence); never stop the leader early — tail diffs measure delivery robustness, which is half the decision.

Result 2026-10-18 (monartha corpus, 24 delivered / 30 attempted): 1. space-bunny-free — deepest true findings, fastest (~31s), but ~20% no-delivery when it wanders; 2. glm-5.3-flash-free — near-equal depth, best calibration, killed by 2×420s provider timeouts; 3. nemotron-3.5-super-vl-free — 100% delivery, shallowest, one hallucinated major. All $0. Pin: reviewer → space-bunny, fallback/second-opinion → glm-5.3-flash. Spark-1.3-contributor via OR is blocked by the user's own privacy guardrails regardless of quality.
