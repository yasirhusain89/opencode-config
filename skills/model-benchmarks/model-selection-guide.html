1. How to choose

Role → benchmark map: reviewer ≈ DeepSWE v1.1 (real SWE tasks) · researcher ≈ Terminal-Bench 4.0 (agentic terminal use) · technical Q&A ≈ SWE-Atlas-QnA · general/code knowledge ≈ Engineering Index · latency/price roles (docs, domain chat) ≈ speed + $/1M. Rules: every pinned model must resolve to data (unmatched = unreviewed); a strict-dominance alternative on all six axes is a free switch modulo provider availability; volume decides cost-vs-quality (reviewer runs constantly → $/task; security runs rarely → quality); scores are model×harness — a number earned on Codex only approximately transfers to opencode agents.

Click any ⇅ column header to sort. “—” = no data (never read as zero). “~” = inferred, see footnotes.

15. Operational resilience: 429s, reliability, deprecation

No native failover exists in opencode (confirmed vs config schema + feature request #7602): single agent.<name>.model, no retry/backoff keys — only provider.<id>.options.timeout/headerTimeout/chunkTimeout. At 300+ calls/hr the loop dies on 429 unless you add rotation. Achievable design: (1) paired agents (reviewer + reviewer-fallback, different vendors) switched manually or via wrapper catching 429/FreeUsageLimitError with exp-backoff+jitter and --model rotation; (2) OpenRouter models:[primary,fallback] + allow_fallbacks for automatic in-gateway failover (+ per-endpoint uptime API for routing); (3) community plugins/proxy (auto-fallback, circuit-breaker) — vet before trusting; (4) never use *-free Zen IDs for 25-step loops. Reliability notes: Zen has no status page/SLA (quota, not uptime, is the failure mode); Groq has a real per-model status page; Google free = sheddable; NVIDIA trial has silent removals.

Deprecation risk (2026-09-16): HIGH — DS V4 Pro retiring (DeepSeek routes deepseek-v4-pro → V4.1-Flash since Sep 14; v4-flash retired Sep 10; Baseten EOL Sep 25) · HIGH — MiniMax M2.7 (NVIDIA EOL Jul 27) · MEDIUM — Kimi K2.6/K2.7-Code (Baseten EOL Sep 25; K2.8 preview out) · MEDIUM — GLM-5.2/5.1 (superseded; NIM degradation reports) · LOW: Spark 1.3, GLM-5.3(+Flash), Gemini 3.8, Kimi K3, M3, Luna/Sol, Sonnet 5/4.6. Weight boring+stable; re-check via Zen deprecation table + inventory.

16. Compliance, exit options, caching (2026-09-16)

Compliance: strongest — Groq (SOC 2 II + DPA + conditional BAA), Google paid (SOC + DPA + EU regions + HIPAA path), NVIDIA (SOC + DPA), OpenRouter Enterprise (SOC 2 + signed DPA + EU lock + ZDR). Weakest — DeepSeek direct (PRC storage, DE/IT blocks, no SOC2/BAA), Zen/Z.ai/Moonshot/MiniMax (no published SOC 2 or BAA; Z.ai has API DPA). Disqualifiers for regulated/financial data: direct CN/SG routes without signed DPA + region pin; Zen free / AI-Studio unpaid (training use); default OR routing without ZDR/no-train.

Open-weights exit (leverage + self-host endgame): STRONG — DeepSeek V4 (MIT, Flash 284B best exit), GPT-OSS (Apache, 1×80GB), Qwen3.5/coder (Apache), GLM (MIT/Apache, most permissive CN), Nemotron Super (120B); WEAK — Ultra (550B needs cluster), Kimi (2.8T + custom license), MiniMax (custom), Gemma (custom); NONE — Spark (1.2 weights "coming", not out), Gemini/Grok/Claude (closed).

Caching rules for 25-step loops (cache-read currently 0 in our DB — pure upside): stable prefix ordering (system › sorted tools › repo context › history tail, never reorder); explicit breakpoints for large stable blocks (Anthropic/Qwen syntax); append-only evolution (no timestamps/UUIDs mid-prefix); beat the TTL (5m default, 2h Groq; pin provider/session); stay above minima (1024 OpenAI, 2048/4096 Gemini/Claude) and monitor cache_read tokens. Zen passes provider caching through (watch the Kimi-K3 image bug).

17. Mini-eval protocol (run before re-pinning)

Ten leaderboards lose to ten of your diffs. Corpus: 10 recent real diffs (bugfix, refactor, feature, dep bump, test-only, security-sensitive), frozen. Contenders: 2–3 (same frozen reviewer prompt, temp 0.1, fresh session each, strip model IDs, judge blind). Rubric per run (1–5): true positives · false positives (weight ×3 against) · actionability (concrete fix + file:line) · format compliance · log $/run + wall time. Decision: rank by (blocking issues caught − false alarms), break ties by $/run. Cost ≈ 30 runs × per-run cost — compute from §13 first. Re-run quarterly or when the shortlist changes; log scorecards under skills/model-benchmarks/snapshots/evals/.

Clean proprietary-code API paths: Groq (+ZDR), Z.ai API (DPA no-storage), Kimi API (FAQ claim, ToS caveat — get it in writing), DeepSeek direct (opt out first). Avoid for secrets: all contributor/free trainers, NVIDIA trial (logged), OpenRouter free without ZDR + train-opt-out.
